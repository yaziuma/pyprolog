# PyProlog 非ブロッキング入力述語設計書

## 概要

PyPrologライブラリに`peek_char/1`および`at_end_of_stream/0`述語を追加し、ブロッキングI/Oによる入力待ちを解決する非破壊的入力検査機能を提供する。

**現在の課題:**
- `get_char/1`述語は入力があるまで無限に待機（ブロッキング）
- 対話的アプリケーションで制御フローを奪われる
- 入力の事前確認手段がない
- ライブラリとして利用時に予期しない停止が発生

**本設計による解決:**
- 入力を消費せずに先読みチェックが可能
- ストリーム状態の非破壊的確認
- 条件付き入力処理の実現
- ライブラリ利用者が制御可能な入力フロー

---

## 1. peek_char/1述語設計

### 1.1 機能概要

**目的:** 次の文字を先読みし、ストリーム位置を変更せずに文字情報を取得する

**動作:**
- 入力ストリームの次の文字を取得
- ストリームの読み取り位置は変更しない
- 同一位置で繰り返し呼び出し可能
- バッファ機能により非ブロッキング動作

### 1.2 インプット・アウトプット仕様

**形式:**
```prolog
peek_char(-Char)
peek_char(+Stream, -Char)
```

**インプット:**
- `Stream` (Optional): 対象入力ストリーム（省略時は現在のストリーム）

**アウトプット:**
- `Char`: 次の文字のAtom
  - 通常文字: `'a'`, `'1'`, `' '` など
  - EOF: `'end_of_file'`

**成功条件:**
- ストリームが読み取り可能
- バッファ機能をサポートするストリーム

**失敗条件:**
- ストリームがバッファ機能をサポートしない
- ストリームエラー

### 1.3 処理フロー（ライブラリ利用考慮）

```
1. ストリーム取得
   ├── 引数指定あり → 指定ストリーム使用
   └── 引数省略 → 現在の入力ストリーム使用

2. ストリーム検証
   ├── peek_charサポート確認
   ├── バッファ機能確認
   └── 権限チェック

3. 非破壊的文字取得
   ├── バッファに文字あり → 即座に返却
   ├── バッファ空 → 非ブロッキング読み込み試行
   └── EOF到達 → end_of_fileアトム返却

4. 結果統合化
   ├── 文字 → Atom変換
   ├── 引数変数 → unification
   └── 成功/失敗判定

5. ライブラリ利用者への結果返却
   ├── 成功: バインディング環境更新
   └── 失敗: 空のイテレーター
```

## 2. at_end_of_stream/0述語設計

### 2.1 機能概要

**目的:** 現在の入力ストリームがEOF（End of File）に到達しているかを非破壊的に確認する

**動作:**
- ストリームの現在位置でEOF状態を判定
- ストリーム位置は変更しない
- バッファ情報に基づく即座の判定
- ブロッキングしない状態確認

### 2.2 インプット・アウトプット仕様

**形式:**
```prolog
at_end_of_stream
at_end_of_stream(+Stream)
```

**インプット:**
- `Stream` (Optional): 対象入力ストリーム

**アウトプット:**
- 成功: ストリームがEOFに到達している
- 失敗: ストリームにまだデータが残っている

**状態情報:**
- `not`: データが利用可能
- `at`: EOF位置に到達
- `past`: EOF位置を過ぎている

### 2.3 処理フロー（ライブラリ利用考慮）

```
1. ストリーム特定
   ├── 引数あり → 指定ストリーム
   └── 引数なし → 現在の入力ストリーム

2. 状態検証機能確認
   ├── at_end_of_streamメソッド存在確認
   ├── ストリーム権限確認
   └── バッファ状態確認

3. 非破壊的EOF判定
   ├── バッファ位置情報確認
   ├── 利用可能データ確認
   └── EOF状態判定

4. ライブラリ安全性考慮
   ├── 例外ハンドリング
   ├── ストリーム状態保持
   └── エラー状況の適切な報告

5. 結果返却
   ├── EOF到達 → 述語成功
   ├── データあり → 述語失敗
   └── エラー → 適切な例外発生
```

## 4. ライブラリ利用シナリオ

### 4.1 対話的アプリケーション開発

**課題解決:**
```python
# Before: ブロッキングで制御不能
result = runtime.query("get_char(X)")  # 入力まで停止

# After: 制御可能な入力フロー
if runtime.query("at_end_of_stream"):
    handle_no_input()
else:
    next_char = runtime.query("peek_char(X)")
    if should_process(next_char):
        actual_char = runtime.query("get_char(Y)")
```

### 4.2 パーサー実装

**高度なトークン解析:**
```prolog
% 数字列の事前判定
parse_number_if_available(Number) :-
    peek_char(First),
    First >= '0', First =< '9',
    read_number_sequence(Number).

% 条件付きトークン読み取り
conditional_token_read(Token) :-
    \+ at_end_of_stream,
    peek_char(Next),
    determine_token_type(Next, Type),
    read_token_by_type(Type, Token).
```

### 4.3 ストリーム処理パイプライン

**効率的なデータ処理:**
```python
def process_input_stream(runtime):
    """非ブロッキングストリーム処理"""
    while not runtime.query("at_end_of_stream"):
        # 先読みで処理判定
        peek_result = runtime.query("peek_char(X)")
        if should_skip_character(peek_result):
            runtime.query("get_char(_)")  # スキップ
        else:
            process_character(runtime.query("get_char(Y)"))
```
