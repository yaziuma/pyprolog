## 調査パケットA：existence_error の仕様と現在挙動

### 判定ロジックの現状
- `existence_error` を投げるのは `LogicInterpreter.solve_goal` のみで、条件は「`actual_goal.functor` が `Atom` かつ `true`/`fail` 以外で、`rules_by_pred` に `(functor, arity)` キーが存在しない場合」です。`rules_by_pred` だけを根拠にしています。【F:pyprolog/runtime/logic_interpreter.py†L519-L532】
- `Runtime.execute` で builtins や演算子は先に処理されるため、`solve_goal` は基本的にユーザー定義述語のみを対象にし、未定義判定も `rules_by_pred` のみです。【F:pyprolog/runtime/interpreter.py†L651-L765】【F:pyprolog/runtime/logic_interpreter.py†L519-L532】

### `assertz -> retract -> p(_)` の再現経路（存在扱いの崩壊ポイント）
1. `assertz(p(1)).` で `DynamicAssertZPredicate` が `LogicInterpreter.add_rule` を呼び出し、`rules` と `rules_by_pred` / `rules_by_pred_arg0` を更新（末尾追加）。【F:pyprolog/runtime/builtins.py†L299-L340】【F:pyprolog/runtime/logic_interpreter.py†L167-L175】
2. `retract(p(1)).` で `DynamicRetractPredicate` が `LogicInterpreter.remove_rule` を呼び出し、該当エントリ削除時に `_remove_from_index` が `rules_by_pred` のバケットを空なら削除します。【F:pyprolog/runtime/builtins.py†L437-L506】【F:pyprolog/runtime/logic_interpreter.py†L109-L137】【F:pyprolog/runtime/logic_interpreter.py†L177-L183】
3. `p(_)` を実行すると `solve_goal` が `rules_by_pred` にキーがないことを根拠に `existence_error` を投げます（述語レジストリがないため、節ゼロ＝不存在扱い）。【F:pyprolog/runtime/logic_interpreter.py†L519-L532】

### “述語の存在”の現在の定義（暗黙）
- `rules_by_pred` のキーの有無が存在判定になっており、節が0になると「存在しない」と解釈されます。レジストリ等の独立メタデータはありません。【F:pyprolog/runtime/logic_interpreter.py†L29-L44】【F:pyprolog/runtime/logic_interpreter.py†L519-L532】

## 調査パケットC：インデクス更新モデル（Phase2と整合）

### インデクス構造の現状
- `rules_by_pred`（述語/アリティの一次インデクス）と `rules_by_pred_arg0`（第1引数の簡易二次インデクス）を持ち、`rules_index` は `rules_by_pred` への参照として設定されています。【F:pyprolog/runtime/logic_interpreter.py†L29-L44】
- arg0 二次インデクスは `Atom/Number/String` のみ対応。複合項/リスト/変数はフォールバックで一次インデクス検索になります。【F:pyprolog/runtime/logic_interpreter.py†L70-L91】【F:pyprolog/runtime/logic_interpreter.py†L145-L166】

### `_refresh_index_if_needed()` の dirty 条件と更新内容
- dirty 判定は「`len(self.rules) != self._rules_len`」のみで、件数が変わればフル再構築です。差分更新はありません。【F:pyprolog/runtime/logic_interpreter.py†L35-L49】
- `add_rule/remove_rule` では差分更新（`_add_to_index` / `_remove_from_index`）を行い、同時に `_rules_len` を更新するため、通常は `_refresh_index_if_needed` が走りません。【F:pyprolog/runtime/logic_interpreter.py†L93-L137】【F:pyprolog/runtime/logic_interpreter.py†L167-L185】

### 動的更新に必要な更新ポイント（現状からの整理）
- asserta/assertz/retract ではインデクスの差分更新が既に行われているため、少なくとも「挿入/削除による index 更新」は現行コード内で完結しています。【F:pyprolog/runtime/logic_interpreter.py†L93-L137】【F:pyprolog/runtime/logic_interpreter.py†L167-L185】
- ただし「述語が存在する」情報が `rules_by_pred` と同一なので、動的更新後に節数が0になった場合の存在扱いを別に持つ必要がある（Phase2のインデクス追加だけでは解決しない）。【F:pyprolog/runtime/logic_interpreter.py†L29-L44】【F:pyprolog/runtime/logic_interpreter.py†L519-L532】
