# Prolog処理系の述語存在挙動 詳細調査（ユーザ視点）

## 調査目的（最初に必ず書く）

```
Prolog処理系における「述語の存在（existence）」の意味論を、
主要処理系（SWI-Prolog / YAP / GNU Prolog）の
“ユーザ視点の実挙動”として正確に把握する。

pyprolog の設計判断材料にするため、
仕様・実機挙動・公式ドキュメントの根拠を収集する。
```

---

## 調査制約（本環境）
- 外部ドキュメント/実機実行環境へのアクセスが制限されており、SWI-Prolog / YAP / GNU Prolog の公式ドキュメントや実機ログを取得できませんでした（curl が 403 で失敗）。
- そのため、本ファイルでは **推測を行わず**、各項目を **未確認** として整理します。外部環境での確認が必須です。

## 述語存在レジストリ導入時の責務分割（案・図）
```
┌─────────────────────┐
│ Runtime             │
│ - rules(節集合)     │
│ - builtins dispatch │
└─────────┬───────────┘
          │ asserta/assertz/retract 呼び出し
          v
┌─────────────────────┐
│ Builtins            │
│ - clause 解析/検証  │
│ - LogicInterpreter  │
│   への操作依頼      │
└─────────┬───────────┘
          │ add/remove
          v
┌───────────────────────────────────┐
│ LogicInterpreter                  │
│ - rules_by_pred / arg0 index      │
│ - predicate registry (新設)       │
│ - solve_goal: existence 判定       │
└───────────────────────────────────┘
```
- Runtime は「節集合の所有」と「builtin のルーティング」を担い、述語存在の判定は LogicInterpreter 側に集約する想定。
- Builtins は clause の構造検証と LogicInterpreter への追加/削除依頼までを担い、レジストリ更新は LogicInterpreter 内の add/remove に集約する想定。
