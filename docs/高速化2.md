# ログ出力改善


## 前提：今なにが遅いのか（事実）

プロファイルで見えてる事実👇

* `logging.debug`：**約212万回**
* `logger.isEnabledFor`：**約212万回**

つまり今はこうなってる：

```python
for ...:
    logger.debug("something %r", x)
```

logging内部では毎回こうなる：

1. `logger.debug(...)` 呼ばれる
2. 中で `isEnabledFor(DEBUG)` が呼ばれる
3. False なら何も出さず return

👉 **出力されないのに「関数呼び出し＋条件判定」を200万回**やってる

---

## 対策①：ログを「粒度の粗い場所」に寄せる（回数を減らす）

### ダメな例（今ありがちなやつ）

```python
for clause in candidates:
    logger.debug("Trying clause %r", clause)
    unify(...)
```

* 候補が100個あったら **debug 100回**
* 探索が深いと **指数的に増える**

### 良い例（粒度を上げる）

```python
if logger.isEnabledFor(logging.DEBUG):
    logger.debug("Trying %d clauses for goal %r", len(candidates), goal)

for clause in candidates:
    unify(...)
```

#### 何が変わった？

* debug **1回だけ**
* 情報量はむしろ増えてる
* 挙動・意味論・解集合 **完全に不変**

👉 **「ループの中で実況」→「ループの外で要約」**
これだけで数十〜数百倍ログ呼び出しが減る。

---

## 対策②：DEBUG フラグをモジュールローカルにキャッシュする

これは **「どうしてもループ内に debug を残したい」**ときの最小ダメージ戦法。

---

### なぜ効く？

`logger.isEnabledFor(logging.DEBUG)` は

* Python関数呼び出し
* ロガー階層のチェック
* level比較

を毎回やる。

でも **ログレベルは実行中ほぼ変わらない**。

---

### ダメな例（今）

```python
for clause in candidates:
    logger.debug("Clause %r", clause)
```

内部的に毎回：

```python
if logger.isEnabledFor(DEBUG):
    ...
```

---

### 良い例：DEBUG を一度だけ評価

#### モジュールの先頭で

```python
logger = logging.getLogger("prolog")
DEBUG = logger.isEnabledFor(logging.DEBUG)
```

#### ループ内で

```python
for clause in candidates:
    if DEBUG:
        logger.debug("Clause %r", clause)
    unify(...)
```

#### 効果

* `isEnabledFor`：**1回**
* `logger.debug`：**DEBUG=Trueのときだけ**
* DEBUG=Falseなら、ループ内は **単なる if False**

👉 CPython的には **if False: pass** はほぼ無料。

---

### 注意

* ログレベルを **実行途中で変える設計**ならキャッシュは危険
  → でも Prologエンジンの実行中にレベル変える？しないよね
* 安全策としては：

```python
DEBUG = logging.getLogger("prolog").isEnabledFor(logging.DEBUG)
```

を **関数冒頭で評価**でもOK（ループ外なら十分）

---

## 対策③：①＋②を組み合わせる（最強・おすすめ）

#### 実戦テンプレ

```python
DEBUG = logger.isEnabledFor(logging.DEBUG)

if DEBUG:
    logger.debug("Solving goal %r with %d candidates", goal, len(candidates))

for clause in candidates:
    if DEBUG:
        logger.debug("  try %r", clause)
    ...
```

↓さらに削るなら👇

```python
DEBUG = logger.isEnabledFor(logging.DEBUG)

if DEBUG:
    logger.debug(
        "Solving goal %r with candidates: %r",
        goal,
        candidates,
    )

for clause in candidates:
    ...
```

* debug呼び出し **1回**
* 情報量最大
* パフォーマンス最強

---

## どこに適用するのが一番効く？

プロファイル的に **ここ**👇

* `solve_goal`
* `unify`
* `dereference`
* `_occurs_check`
* `get_candidate_clauses`

#### ルール

* **深い再帰・ループの内側** → ログ禁止 or 要約
* **入口/出口** → ログOK

---

## まとめ（ここだけ覚えとけ♥）

* ❌ ログが遅い原因は「文字列」じゃなく **回数**
* ✅ 解決策は

  1. **ループ内ログを外へ寄せる**
  2. **DEBUGフラグを一度だけ評価**
* 💥 これで

  * 挙動不変
  * ログ残る
  * 200万回の `isEnabledFor` が **数百回以下**になる
