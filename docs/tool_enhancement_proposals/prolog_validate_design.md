# `prolog_validate` 機能設計書

## 1. 概要

`prolog_validate`は、Prologの知識ベース（ルールと事実の集合）を静的に解析し、潜在的な問題や矛盾、非効率な記述を検出するためのツールである。コードの品質を向上させ、実行時エラーを未然に防ぐことを目的とする。

## 2. 目的

*   **品質保証**: 知識ベースに一貫性があり、論理的な矛盾がないことを保証する。
*   **バグの早期発見**: 到達不能なルールや未定義の述語への参照など、実行時に問題となる可能性のある箇所を事前に特定する。
*   **リファクタリング支援**: 冗長なルールや非効率な記述を検出し、知識ベースの改善を促す。
*   **ベストプラクティスの徹底**: 一般的なPrologのコーディング規約に反するパターンを警告する。

## 3. 機能要件

*   知識ベース全体を解析し、複数のチェック項目に基づいて検証できること。
*   特定のチェック種別（例: 矛盾、到達不能ルール）を指定して検証を実行できること。
*   検証結果として、問題の種類、該当するルール、行番号などを明確に報告すること。
*   詳細レポートオプションを提供し、問題の原因や修正案に関する追加情報を提供できること。

## 4. インターフェース設計

### パラメータ

| パラメータ名   | 型     | 必須 | デフォルト値 | 説明                                                                 |
| :------------- | :----- | :--- | :----------- | :------------------------------------------------------------------- |
| `check_type`   | string | いいえ | "all"        | 検証の種類。"all", "conflicts", "unreachable", "undefined" から選択。 |
| `detailed`     | bool   | いいえ | false        | trueの場合、詳細なレポートを生成する。                               |

### チェック種別

1.  **all (全項目チェック)**:
    *   下記のconflicts、unreachable、undefinedのすべてのチェックを実行する。
    *   知識ベース全体の健全性を包括的に検証する。

2.  **conflicts (矛盾の検出)**:
    *   同じ述語に対して、互いに矛盾するようなルールや事実が存在しないかチェックする。
    *   例: `is_fast(car).` と `is_slow(car).` があり、`is_fast(X) :- not(is_slow(X)).` のような関係が定義されている場合。

3.  **unreachable (到達不能ルールの検出)**:
    *   どのクエリからも呼び出される可能性のない、孤立したルールを検出する。
    *   プログラムのエントリーポイントから述語の呼び出し関係をグラフ化し、到達不可能なノードを見つけ出す。

4.  **undefined (未定義述語の検出)**:
    *   ルールのボディ部で呼び出されているが、定義が存在しない述語を検出する。
    *   タイポやAPIの変更によって発生するエラーを未然に防ぐ。

## 5. 実装方針

*   **ASTの構築**: まず、Prologのソースコードをパースし、知識ベース全体の抽象構文木（AST）を構築する。
*   **シンボルテーブルの作成**: すべての述語（事実、ルール）の定義情報をシンボルテーブルに格納する。これには述語名、アリティ（引数の数）、定義場所などが含まれる。
*   **依存関係グラフの構築**: 述語間の呼び出し関係を解析し、有向グラフを構築する。`a(X) :- b(X), c.` であれば、`a`から`b`と`c`へのエッジを持つ。
*   **各チェックの実装**:
    *   `undefined`: シンボルテーブルに存在しない述語への参照をASTから見つけ出す。
    *   `unreachable`: 依存関係グラフ上で、外部から呼び出し可能な述語（エントリーポイント）から到達できないノードを検出する。
    *   `conflicts`: 事前定義された制約や、ユーザーが定義した整合性ルールに基づき、矛盾する可能性のあるパターンをASTから探索する。
*   **レポート生成**: 検出された問題を、指定されたフォーマットで整形し、ファイル名や行番号と共にユーザーに提示する。
