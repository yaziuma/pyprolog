# `prolog_explain` 機能設計書

## 1. 概要

`prolog_explain`は、指定されたPrologクエリの推論過程を可視化し、ユーザーがどのように解が導出されたか、あるいはなぜ失敗したかを理解するのを助けるためのツールである。実行トレースを記録し、指定されたフォーマットで分かりやすく表示する機能を提供する。

## 2. 目的

*   **デバッグの効率化**: ルールが期待通りに動作しない場合、どのステップで問題が発生したかを特定しやすくする。
*   **学習支援**: Prologのバックトラッキングや単一化のメカニズムを初学者が視覚的に理解する手助けとする。
*   **複雑なクエリの解析**: 多数のルールが絡み合う複雑なクエリの動作を明確にし、意図しない動作の発見を容易にする。

## 3. 機能要件

*   指定されたクエリの実行トレースを取得できること。
*   トレースには、呼び出されたゴール、マッチしたルール（事実または節）、変数の束縛、バックトラックの発生などが含まれること。
*   推論の深さを指定し、出力の詳細度を制御できること。
*   トレース結果を複数の形式（テキスト、ツリー、JSON）で出力できること。
*   クエリが成功した場合と失敗した場合の両方の推論過程を説明できること。

## 4. インターフェース設計

### パラメータ

| パラメータ名 | 型      | 必須 | デフォルト値 | 説明                                       |
| :----------- | :------ | :--- | :----------- | :----------------------------------------- |
| `query`      | string  | はい | -            | 説明対象のPrologクエリ文字列。             |
| `depth`      | integer | いいえ | 無制限       | 表示するトレースの最大の深さ。             |
| `format`     | string  | いいえ | "text"       | 出力形式。"text", "tree", "json"から選択。 |

### 出力形式

1.  **text形式**:
    *   実行ステップを時系列でプレーンテキストとして表示する。
    *   デバッグログのような形式で、シンプルで読みやすい。

    ```
    CALL: my_query(X, 'a')
      EXIT: my_query('b', 'a')
    SUCCESS: X = 'b'
    REDO: my_query(X, 'a')
      FAIL: my_query(X, 'a')
    FAIL
    ```

2.  **tree形式**:
    *   ゴールの呼び出し関係を階層的に表示する。
    *   推論の全体像を把握しやすい。

    ```
    - my_query(X, 'a')
      - SUCCESS: X = 'b'
      - FAIL
    ```

3.  **json形式**:
    *   トレース情報を構造化データとして出力する。
    *   他のツールとの連携や、プログラムによる解析が容易になる。

    ```json
    {
      "query": "my_query(X, 'a')",
      "status": "SUCCESS",
      "solutions": [{"X": "'b'"}],
      "trace": [
        {"event": "CALL", "goal": "my_query(X, 'a')", "depth": 1},
        {"event": "EXIT", "goal": "my_query('b', 'a')", "depth": 1}
      ]
    }
    ```

## 5. 実装方針

*   Prologインタープリタのコアエンジンに、トレース情報を記録するためのフックを追加する。
*   `CALL` (ゴールの呼び出し), `EXIT` (成功), `FAIL` (失敗), `REDO` (バックトラック) の各イベントで、現在のゴール、変数の状態、深さなどの情報をログとして収集する。
*   `prolog_explain`ツールは、この収集されたログを受け取り、指定された`format`パラメータに応じて整形し、ユーザーに出力する。
*   既存の実行ロジックへの影響を最小限に抑えるため、トレース機能は明示的に有効化された場合にのみ動作するように設計する。

## 6. ユースケース

*   **開発者がルールのデバッグを行う**: `different_locations(X, Y)`というクエリが期待通りの結果を返さない時、`prolog_explain`を使ってどの`location`の事実で失敗しているかを確認する。
*   **自動テストでの利用**: テストが失敗した際に、JSON形式でトレース情報を出力し、CI/CDシステムで解析・レポートする。
