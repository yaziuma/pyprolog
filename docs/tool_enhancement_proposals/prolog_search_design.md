# `prolog_search` 機能設計書

## 1. 概要

`prolog_search`は、大規模なPrologの知識ベース内から、特定のパターンや条件に合致するルールや事実を効率的に検索するためのツールである。開発者がコードを探索し、理解するのを支援することを目的とする。

## 2. 目的

*   **コードの可読性向上**: 関連するルールや事実を素早く見つけ出し、プログラムの構造やロジックの理解を助ける。
*   **リファクタリングの支援**: 特定の述語がどこで使用されているかを一覧表示し、変更の影響範囲を正確に把握する。
*   **知識の探索**: 大規模な知識ベースから、特定のエンティティや関係性に関する情報を抽出する。
*   **デバッグの効率化**: 問題となっている述語の定義や、関連するルールを迅速に特定する。

## 3. 機能要件

*   述語名、引数のパターン、あるいはルール内のテキストに基づいて検索できること。
*   検索タイプ（述語名のみ、引数、全文検索）を指定できること。
*   検索結果の件数を制限できること。
*   検索結果には、マッチしたルールや事実、ファイル名、行番号などのコンテキスト情報を含めること。

## 4. インターフェース設計

### パラメータ

| パラメータ名    | 型     | 必須 | デフォルト値 | 説明                                                                 |
| :-------------- | :----- | :--- | :----------- | :------------------------------------------------------------------- |
| `pattern`       | string | はい | -            | 検索パターン。例: "location", "location(X, office)", "computer"。      |
| `search_type`   | string | いいえ | "predicate"  | "predicate", "argument", "full_text" から選択。                      |
| `limit`         | int    | いいえ | 100          | 返される結果の最大数。                                               |

### 検索タイプ

1.  **predicate (述語名での検索)**:
    *   指定されたパターンに一致する述語名を持つルールや事実を検索する。
    *   例: `pattern="location"` は `location(desk, office).` や `is_in(X, Y) :- location(X, Y).` の両方にマッチする可能性がある（定義と使用箇所の両方）。

2.  **argument (引数パターンでの検索)**:
    *   指定された構造にマッチする引数を持つルールや事実を検索する。
    *   変数をワイルドカードとして扱うことができる。
    *   例: `pattern="location(_, office)"` は、第二引数が `office` である `location` の事実すべてにマッチする。

3.  **full_text (全文検索)**:
    *   ルールや事実のテキスト全体（コメント含む）から、指定された文字列を検索する。
    *   特定の定数やコメントがどこに現れるかを調べるのに便利。
    *   例: `pattern="office"` は `location(desk, office).` や `% This rule is for the office.` のようなコメントにもマッチする。

## 5. 実装方針

*   **インデックスの構築（オプション）**: パフォーマンス向上のため、知識ベースを事前に解析し、述語名、引数の構造、テキストトークンなどから検索可能なインデックスを作成する。大規模な知識ベースを頻繁に検索する場合に有効。
*   **ASTベースの検索**:
    1.  知識ベースのソースコードをパースし、ASTを構築する。
    2.  `search_type` に応じてASTを走査する。
        *   `predicate`: 述語名がパターンに一致するノードを探す。
        *   `argument`: 述語の引数部分のASTが、指定されたパターン構造と単一化可能かチェックする。
        *   `full_text`: ASTを構築する前の生のテキスト、あるいはASTノードをテキストに変換したものを対象に文字列検索を行う。
*   **結果のフォーマット**:
    *   見つかった各項目について、ファイルパス、開始行番号、終了行番号、およびマッチしたコードのスニペットを収集する。
    *   収集した情報を整形し、ユーザーにリストとして返す。`limit` パラメータに達したら検索を終了する。

## 6. ユースケース

*   **影響範囲の調査**: `prolog_search(pattern="old_predicate", search_type="predicate")` を実行し、リファクタリング対象の古い述語がどこで使われているかをすべて洗い出す。
*   **特定のデータ構造の探索**: `prolog_search(pattern="user(_, _, 'admin')", search_type="argument")` を実行し、「admin」権限を持つユーザーデータを定義している事実をすべて見つける。
*   **関連ロジックの発見**: `prolog_search(pattern="tax_calculation", search_type="full_text")` を実行し、税計算に関連する可能性のあるルールやコメントを広範囲に探索する。
